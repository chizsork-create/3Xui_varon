# План: 3Xui Varon

## Цель

Собрать воспроизводимый установщик для чистой Ubuntu 24.04: актуальные
3X-UI/Xray, Nginx-маршрутизация на одном публичном `443`, безопасные значения
по умолчанию и отдельный статический сайт-заглушка в визуальном языке PWA.

Это не обновление существующих серверов «на месте». Первая установка и все
проверки выполняются на чистом тестовом VPS. Немецкий и нидерландский узлы
остаются рабочими до подтверждённой миграции.

## Что меняем в базе

Текущий `x-ui-latest.sh` содержит монолитный установщик. В нём есть
принудительная очистка прежней установки, временное выключение UFW и старый
XHTTP-прокси через `grpc_pass`. Это не годится как безопасная база для
повторных запусков.

Новая версия будет разбита на небольшой входной скрипт и проверяемые модули:

```
bin/varon
lib/preflight.sh
lib/packages.sh
lib/security.sh
lib/three_x_ui.sh
lib/nginx.sh
lib/inbounds.sh
lib/backup.sh
lib/doctor.sh
cover-site/
tests/
```

## Архитектура сети

1. Один публичный вход: TCP 443. Nginx `stream` выбирает backend по SNI.
2. Домен панели обслуживается Nginx HTTP/TLS на localhost; там же обычный
   HTTPS-сайт, подписка, XHTTP и Trojan gRPC.
3. Отдельный reality-домен через `stream` передаётся Xray без TLS-терминации.
4. XHTTP использует Unix-сокет и корректный HTTPS `proxy_pass`, а не
   `grpc_pass`. Для клиентов отдаётся ALPN `h2,http/1.1`.
5. Все backend-порты слушают только localhost/Unix-сокет. Открывать наружу
   8443, порт панели или временные порты не требуется.
6. Стартовый набор входов: VLESS+REALITY, VLESS+XHTTP+TLS, Trojan+gRPC+TLS.
   WebSocket остаётся опциональным совместимым резервом.

### Клиент и единая подписка — обязательный результат install

После установки создаётся первый клиент с безопасно сгенерированными UUID,
паролем Trojan и `subId`. В одной URL-подписке для него должны быть доступны:

1. VLESS + REALITY — основной независимый маршрут.
2. VLESS + XHTTP + TLS — вариант через HTTPS-сайт.
3. Trojan + gRPC + TLS — независимый HTTPS-резерв.
4. VLESS + WebSocket + TLS — только если выбран опциональный compatibility
   profile.

У всех вариантов один `subId`; установщик проверяет, что URL подписки реально
выдаёт каждую ссылку, а не только создаёт записи в БД. Секреты не попадают в
логи, README и shell history: в конце выводится только URL подписки и путь к
локальному защищённому state-файлу.

Для 3X-UI v3.7 клиент создаётся через официальный `/panel/api/clients/add` и
прикрепляется к массиву inbound ID одной транзакцией. Прямая запись в SQLite
запрещена: начиная с актуальных релизов клиент имеет собственные таблицы и
миграции, которые панель должна вести сама.

### Регрессии XHTTP, которые покрываем тестами

- В generated `hosts` для XHTTP всегда записываются основной домен в `sni` и
  `override_sni_from_address=0`; ссылка подписки не должна терять SNI.
- Nginx-location XHTTP использует HTTPS-прокси к Unix-сокету с отключённой
  буферизацией. `grpc_pass` допустим только для Trojan/gRPC, не для XHTTP.
- Проверяется полный путь временным Xray-клиентом: профиль из подписки →
  `https://<домен>:443` → Nginx → Unix-сокет → Xray → внешний HTTPS-запрос.
- UFW не открывает panel, subscription, WS, Trojan, Reality backend и
  диагностические порты наружу. Тест проверяет, что доступны только SSH,
  80/tcp и 443/tcp (и 443/udp, если выбран HTTP/3).

## Домен и бесплатный DNS

Установщик не привязывается к платному регистратору или к API конкретного
DNS-провайдера. При запуске он спрашивает:

1. Базовый домен, полученный у бесплатного DNS/subdomain-провайдера.
2. Subdomain для панели, сайта и подписки.
3. Subdomain для REALITY; по умолчанию `reality`.

Например, `example.free-dns.tld` + `vpn` создают `vpn.example.free-dns.tld`, а
Reality получает `reality.example.free-dns.tld`. Скрипт показывает требуемые
A/AAAA-записи, проверяет, что они указывают на VPS, и только затем выпускает
Let's Encrypt сертификат. Он не просит логин или API-ключ DNS-провайдера.

Отдельным необязательным этапом позднее можно добавить адаптеры DNS API, но
базовый install всегда должен работать после ручного создания двух записей.

## Безопасность по умолчанию

- Установщик работает только с явным `install` и не удаляет существующие
  данные. Для существующего узла будут отдельные команды `doctor`, `backup`
  и `migrate`.
- Перед любой конфигурационной заменой: архив БД 3X-UI, Nginx-конфигов,
  сертификатов и state-файла; запись через временный файл; `nginx -t` до
  reload.
- UFW: deny incoming, allow outgoing; SSH-порт пользователя, 80/tcp и
  443/tcp. Сначала добавляются правила, затем включается firewall.
- Fail2ban для SSH: 3 ошибки за 10 минут, бан на 24 часа. Без широкого
  `ignoreip`, чтобы динамический адрес не превращался в постоянный обход.
- `unattended-upgrades` только для security-обновлений; журнал обновлений и
  ручная команда обновления панели.
- Панель не получает публичный прямой порт; доступ только через HTTPS,
  случайный base path и сильные учётные данные, заданные при установке.
- Версии 3X-UI фиксируются в release manifest. Скачиваемый архив проверяется
  контрольной суммой; «скачать и исполнить main-ветку» исключается.

## Сайт-заглушка

Сайт будет самостоятельным статическим набором файлов, без API PWA,
пользовательских данных, Service Worker и закрытых маршрутов.

- Визуальный язык берём из PWA: типографика, сетка, цвет и характер плиток.
- Главная страница и несколько плиток. Клик по любой плитке открывает
  доступный диалог «Раздел в разработке».
- Нет ссылок на панель, подписку, VPN, диагностику или server-side API.
- Перед кодированием создаётся и утверждается отдельный визуальный концепт.

## Этапы

### 1. База и защита от регрессий

- Зафиксировать supported OS: чистая Ubuntu 24.04.
- Добавить ShellCheck, shfmt и минимальные тесты генерации конфигов в CI.
- Вынести параметры в один typed state/config файл.
- Добавить `--dry-run` и понятные preflight-проверки DNS, портов, прав root,
  версии ОС и свободного места.
- Добавить интерактивный ввод базового домена и двух subdomain, вывод готовых
  DNS-записей и ожидание их распространения до выпуска сертификата.

### 2. Безопасный install/backup/doctor

- Реализовать атомарную генерацию и rollback Nginx/state.
- Реализовать firewall, Fail2ban, security updates и service hardening.
- Добавить резервную копию и проверку восстановления на тестовом VPS.

### 3. Транспортные шаблоны

- Реализовать SNI-router и локальные backend'ы.
- Добавить XHTTP с корректным HTTPS Unix-socket proxy и ALPN.
- Добавить Reality, Trojan gRPC и опциональный WebSocket.
- Автоматически проверить: TLS/SNI, подписку, каждый профиль через временный
  Xray-клиент, `nginx -t`, статусы systemd и UFW.

### 4. Заглушка PWA

- Изучить только публичные визуальные компоненты PWA.
- Утвердить концепт, собрать статический сайт, проверить desktop/mobile,
  клавиатуру и `prefers-reduced-motion`.
- Подключить сайт как обычный Nginx webroot.

### 5. Тестовая установка и миграция

- Прогнать с нуля на тестовом VPS.
- Сравнить доступность прямой и Nginx-схемы, собрать логи Xray/Nginx.
- Только после твоего подтверждения: backup немецкого узла, dry-run и
  миграция с планом отката.

## Готовность

Релиз считается готовым, когда чистая установка проходит CI и ручный test
matrix, все публичные сервисы доступны только на ожидаемых портах, сайт не
содержит PWA/API-данных, а backup + rollback проверены практически.
